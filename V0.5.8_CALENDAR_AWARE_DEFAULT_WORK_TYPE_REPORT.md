## 1. Problem (Problem Statement)

Dotychczas panel rejestracji czasu pracy (`ReportingPanel`) ustalał domyślny rodzaj czasu pracy wyłącznie w oparciu o statyczny dzień tygodnia daty (`isWeekend`):
- Poniedziałek–Piątek: domyślnie `G` (Godziny standardowe),
- Sobota/Niedziela: domyślnie `NS` (Nadgodziny sobota/niedziela), o ile `NS` istniało w słowniku.

Prowadziło to do niespójności biznesowej z backendem:
1. **Święto ustawowe w środku tygodnia** (np. 11.11, 01.05) lub **firmowy dzień wolny** (np. 14.08) otrzymywały domyślnie kod `G`. Próba zapisu takiego wpisu była natychmiast odrzucana przez backend jako niedozwolona w dniu wolnym (`NON_WORKING_DAY_ENTRY_NOT_ALLOWED`).
2. **Sobota/niedziela przekształcona przez zarząd firmy w dzień roboczy** (company working-day override) nadal otrzymywała domyślnie `NS` zamiast standardowych godzin roboczych `G`.

---

## 2. Przyczyna Źródłowa (Root Cause)

Frontend nie odpytywał backendowego serwisu kalendarza zakładowego (`/api/company-calendar/day/:date`) przy zmianie daty raportu ani przy inicjalizacji formularza. Formularz opierał się na uproszczonej funkcji pomocniczej po stronie klienta, ignorującej ustawowe święta w Polsce oraz firmowe wyjątki kalendarzowe (`CompanyCalendarDay`).

---

## 3. Zastosowane Rozwiązanie (Solution Architecture)

1. **Integracja z kalendarzem backendu**:
   - `ReportingPanel` przy zmianie daty lub przy ładowaniu słowników odpytuje istniejący endpoint backendu `GET /api/company-calendar/day/:date`.
   - Wyniki są buforowane w pamięci podręcznej komponentu (`calendarCacheRef: Map<string, CalendarDecision>`), co eliminuje zbędne zapytania sieciowe przy przełączaniu znanych dat.

2. **Dopasowanie funkcji wyboru typu (`getDefaultWorkType`)**:
   - Funkcja obsługuje kontrakt `CalendarDecision` oraz fallback tekstowy.
   - Jeśli dzień jest roboczy (`isWorkingDay: true` z szablonu tygodnia lub wyjątku firmowego) -> zwraca `G`.
   - Jeśli dzień jest wolny w weekend (`source === 'weekend'` lub sobota/niedziela) -> zwraca `NS` (jeśli `NS` istnieje w słowniku).
   - Jeśli dzień jest wolny w środku tygodnia (święto państwowe lub firmowy dzień wolny) -> zwraca `''` (brak automatycznego typu, użytkownik dokonuje świadomego wyboru).
   - Jeśli w słowniku brak kodu `NS` na dzień wolny weekendowy -> zwraca `''` (zapobieganie sugerowaniu błędnego `G`).

3. **Ochrona przed Race Conditions**:
   - Wykorzystanie `activeCalendarFetchDateRef` oraz flagi aktywności `isCurrent` w hooku `useEffect`.
   - W przypadku szybkiej zmiany dat przez użytkownika (np. Data A -> Data B), opóźniona odpowiedź sieciowa dla Daty A jest ignorowana i nie nadpisuje stanu formularza wybranego dla Daty B.

4. **Bezpieczny Fallback (Resilience)**:
   - W przypadku awarii sieci lub błędu endpointu `GET /api/company-calendar/day/:date` (status 500), formularz nie ulega awarii (crash).
   - Zastosowany jest bezpieczny lokalny fallback kalendarzowy (pn-pt -> G, weekend -> NS), a ostateczną regułę bezpieczeństwa wymusza backend przy zapisie.

5. **Interfejs Użytkownika (UI / Select)**:
   - Do listy rozwijanej `<select>` dodano domyślną opcję `<option value="">-- Wybierz rodzaj czasu pracy --</option>`, umożliwiającą czytelne renderowanie stanu bez automatycznego wyboru w dni świąteczne/wolne pn–pt.

## 4. Kontrakt Company Calendar (`GET /api/company-calendar/day/:date`)

Endpoint zwraca status 200 JSON o strukturze:
```json
{
  "date": "YYYY-MM-DD",
  "isWorkingDay": boolean,
  "source": "standard weekday" | "weekend" | "public holiday" | "company override",
  "reason": string | null
}
```

### Matryca Decyzyjna Formularza

| Sytuacja biznesowa | `isWorkingDay` | `source` | Dzień tygodnia | Domyślny rodzaj czasu pracy |
| :--- | :--- | :--- | :--- | :--- |
| **Zwykły dzień roboczy** | `true` | `standard weekday` | Pn–Pt | `G` |
| **Zwykły weekend wolny** | `false` | `weekend` | Sob–Nd | `NS` (gdy `NS` w słowniku) / `''` (brak NS) |
| **Święto państwowe Pn–Pt** | `false` | `public holiday` | Pn–Pt | `''` (nie `G`, nie `NS`) |
| **Firmowy dzień wolny Pn–Pt** | `false` | `company override` | Pn–Pt | `''` (nie `G`, nie `NS`) |
| **Sobota/Niedziela pracująca (override)** | `true` | `company override` | Sob–Nd | `G` (nie `NS`) |
