## 4. Regression-safety assessment

No production business-logic regression was introduced by remediation.

- `getEmployeeReportRows()` pivots solely on `employeeId`: one row per employee;
  FIRST, SECOND, THIRD, and null historical shifts aggregate together.
- `suma = N + O` (worked time including overtime, excluding absences).
- `sumaBezNadgodzin = N + P` (non-overtime work plus paid metadata-classified
  absences); NN is visible only in its dynamic column and enters neither total.
- Closure Control remains `N + O + P`: it starts with `suma`, adds only
  dynamic codes selected by the pre-existing absence-types query, and excludes
  NN. `sumaBezNadgodzin` is deliberately not added, avoiding double counting.
- Reporting Panel retains `FIRST`/`SECOND`/`THIRD` selection and validation.
  Detailed Report still returns `workShift`; Prisma retains `WorkShift` and the
  nullable `work_shift` storage field.

The remediation only removes diagnostics/logging behavior, strengthens tests,
and corrects documentation/screenshots; it does not alter the verified report
or Closure Control calculation.
