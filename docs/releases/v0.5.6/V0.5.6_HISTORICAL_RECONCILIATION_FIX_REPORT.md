## Root Cause
The reconciliation logic in `getReconciliationDiagnostics()` and `getOrderReportRows()` determined "orders in closure" based **only** on the current order status at query time:
- `OPEN` orders (currently active)
- `CLOSED` orders with `completionDate` within the report date range

**Problem**: When an order was closed AFTER the report period (e.g., August report, order closed September 10), it was excluded from the closure report because its `completionDate` was outside the range. However, the work time entries logged in August remained in `totalEmployeeHours`, causing a negative difference (e.g., -35h).

The diagnostic message "Zlecenie nieobjęte raportem zamknięcia" (Order not covered by closure report) was technically accurate for the old logic but violated the business rule of historical stability.

---

## Business Rule Implemented
**Historical reports must be stable.**

> If a work time entry falls within the report date range (`dateFrom <= report.date <= dateTo`), a later change of order status or `completionDate` MUST NOT cause those hours to be removed from the reconciliation control or from the order hours report.

**Example**:
- `report.date = 2026-08-15`
- `report range = 2026-08-01..2026-08-31`
- `order completionDate = 2026-09-10`
- `order status = CLOSED`
- ⇒ Hours from 2026-08-15 MUST still be included in the August report.

## Exact Implementation

### Files Changed
1. `backend/src/routes/analytics.ts` - Core logic fix
2. `backend/tests/analytics.test.ts` - Regression tests

### Changes in `getReconciliationDiagnostics()` (lines 588-620)
Added third OR condition to include OPEN or CLOSED orders with reports in the date range:

```typescript
{
  status: { in: [OrderStatus.OPEN, OrderStatus.CLOSED] },
  reports: {
    some: {
      deletedAt: null,
      date: {
        gte: new Date(`${dateFrom}T00:00:00.000Z`),
        lte: new Date(`${dateTo}T23:59:59.999Z`),
      },
    },
  },
}
```

### Changes in `getOrderReportRows()` (lines 502-518)
Same third OR condition added for closureReport mode:

```typescript
{
  status: { in: [OrderStatus.OPEN, OrderStatus.CLOSED] },
  reports: {
    some: {
      deletedAt: null,
      date: reportDateRange,
    },
  },
}
```

**Key design decisions**:
- Only `OPEN` and `CLOSED` orders qualify (not `SUSPENDED`) - maintains existing semantics
- Uses Prisma `some` for efficient EXISTS subquery on indexed `orderId` + `date`
- Filters `deletedAt: null` to exclude soft-deleted reports
- No double counting: reports are still filtered by `reportDateRange` when summing hours

## Independent Review Rework

### Blockers Identified in Independent Review

1. **Tautological regression test**: The exact 35h summary test mocked `prisma.order.findMany` to return the order whenever `args.where.OR` existed. The pre-fix code ALSO had an OR (with 2 branches), so the test would pass before the fix. It did not verify the specific third branch (`reports.some`) was present.

2. **Contrast test reimplemented logic**: The contrast test reimplemented the entire filtering logic in the mock instead of using the actual query predicate from the production code.

3. **Trailing whitespace**: Committed diff contained trailing whitespace at `backend/tests/analytics.test.ts:2160` (empty line with spaces), causing `git diff --check origin/development...HEAD` to fail.

### Fixes Applied

#### 1. Rewrote Regression Test to Verify Actual Query Structure
The test now:
- Captures the actual `args.where.OR` query sent by production code
- Verifies the query has **3 branches** (not just 2)
- Explicitly checks the 3rd branch structure: `status: { in: ['OPEN', 'CLOSED'] }` + `reports.some { deletedAt: null, date: { gte, lte } }`
- Only returns test data if the 3rd branch is present → **FAILS on pre-fix code (2 branches), PASSES on fixed code (3 branches)**

#### 2. Rewrote Contrast Test to Use Actual Query Predicate
- Mock returns empty for both diagnostic and report-by-order queries (because the order has no reports in range)
- Verifies the query has 3-branch structure
- Confirms order with only out-of-range reports is correctly excluded

#### 3. Fixed Trailing Whitespace
- Removed trailing whitespace from the old test (now rewritten)
- `git diff --check` now passes cleanly
