# v0.6.0 Integrated User Guide — implementation report

## Status and scope

The approved guide implementation is ready for manual acceptance on `feature/v0.6.0-user-guide` (base commit `6389dfb944f4e1b0e1aae5f7f87731717c0ea638`). It has not been committed, merged, tagged, released, or deployed. The production application version remains v0.5.9. User acceptance and release steps remain pending.

The existing Help tab, hash links, version header, docs database guard, fixture, screenshot pipeline, and browser-free validator were extended without changing the application's routing architecture.

Changed files are `frontend/src/help/chapters.tsx`, `frontend/src/components/{HelpView,ContextHelpButton,ReportingPanel,ReportsView,OrdersView,CompanyCalendarView}.tsx`, `frontend/src/App.tsx`, `frontend/src/index.css`, `frontend/docs-screenshots/{capture.spec.ts,manifest.ts,playwright.config.ts}`, two frontend tests, `backend/prisma/docs-seed-data.ts`, its backend test, `scripts/verify-release.sh`, and the related `AGENTS.md`, `README.md`, `CHANGELOG.md`, `PROJECT_STATUS.md`, and `docs/` files. The 21 guide PNGs are under `frontend/public/help/`. Git status is uncommitted on the feature branch; no unrelated tracked files were changed.

## Guide chapters

All 15 chapters from the approved plan are present:

| Chapter | Covered operations |
|---|---|
| Pierwsze kroki | Application purpose and role overview |
| Logowanie | Login, session expiry, theme |
| Ekran główny | Admin/Leader navigation and dashboard |
| Rejestracja czasu pracy | Date, employee/order selection, work-time entry, warning |
| Zmiany I / II / III | Required work shift, disabled absence shift, history |
| Nieobecności | Single-day entry and date range preview |

| Raport wg zleceń | Period and cumulative values, closure/control totals |
| Raport nieobecności | Period grouping and totals |

The five contextual Help actions open `rejestracja-czasu` from ReportingPanel, `raport-hr` from the HR report, `raport-zlecen` from the by-order report, `baza-zlecen` from OrdersView, and `kalendarz` from CompanyCalendarView. A real-browser test verifies every target hash and heading.

## Real application screenshots

The manifest declares 21 PNGs under `frontend/public/help/`: login; Admin and Leader navigation; filled Reporting on desktop and tablet; disabled shift for absence; hours warning; absence range; copied I/II/III labels; orders; HR overview, shift rows and tablet view; by-order and closure/control reports; absence periods; company calendar; dictionaries; imports; dashboard; and export actions. The extra image beyond the 20-item plan is the planned HR tablet variant.

All images were generated by Chromium through `npm run docs:screenshots` against a running application backed by an isolated `_docs` database. The fixture contains only fictional documentation users, employee, order, hours, absence, calendar exception, and import history. The login image has empty fields. The browser test opens every image through its Help chapter at desktop and tablet widths and checks that it loads with nonzero natural width. `docs:validate` checks manifest entries, chapter references, filenames, and files without launching a browser.

## Docs fixture and safety

The `_docs` suffix guard remains unchanged and runs before Prisma client creation; backend guard tests reject non-docs and malformed targets. Two fresh isolated databases, `guide_verify_a_docs` and `guide_verify_b_docs`, received the same 12 migrations and docs seed. Full stored snapshots across users, employees, work-time types, orders, reports, calendar exceptions, and imports matched byte-for-byte (4,552 bytes each). Reseeding A left its snapshot identical. A full screenshot run then used B. No development, demo, client, or production database was used for guide generation.
