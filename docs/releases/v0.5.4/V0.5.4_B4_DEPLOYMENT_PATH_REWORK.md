## 7. Wynik Testu API / Uprawnień dla Typów Niestandardowych (`isSystem = false`)

Test zweryfikował ścieżki HTTP API `/api/work-time-types`:
1. **Edycja `requiresOrder` dla typu niestandardowego (`WKU`)**:
   - `PUT /api/work-time-types/WKU` z `{ requiresOrder: true }` -> **200 OK**, flaga zmieniona w bazie. Typ nie jest zablokowany blokadą systemową.
2. **Blokada edycji `requiresOrder` dla typu systemowego (`G`)**:
   - `PUT /api/work-time-types/G` z `{ requiresOrder: false }` -> **200 OK**, ale pole `requiresOrder` nie zostaje zmienione (zabezpieczenie systemowe aktywne).
3. **Usuwanie typu systemowego (`G`)**:
   - `DELETE /api/work-time-types/G` -> **400 Bad Request** (`"Pozycje słownika systemowego nie mogą być usuwane"`).
4. **Usuwanie typu niestandardowego z raportami (`WKU`)**:
   - `DELETE /api/work-time-types/WKU` -> **400 Bad Request** (`"Nie można usunąć pozycji, ponieważ istnieją zaraportowane godziny z tym kodem"`). Blokada wynika z powiązania danych, a nie ze statusu systemowego.
5. **Usuwanie typu niestandardowego bez raportów (`TMPDEL`)**:
   - `POST /api/work-time-types` (`TMPDEL`) -> **201 Created** (`isSystem = false`).
   - `DELETE /api/work-time-types/TMPDEL` -> **200 OK** (usunięty pomyślnie).
