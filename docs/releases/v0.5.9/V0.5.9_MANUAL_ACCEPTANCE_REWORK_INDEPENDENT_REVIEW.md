## HR report, exports, and aggregation

`getEmployeeReportRows()` groups each report by `employeeId` plus a `ShiftDimension`: `FIRST`, `SECOND`, `THIRD`, `UNSPECIFIED`, or `ABSENCE`. Labels are respectively `I`, `II`, `III`, `Brak danych`, and `Nie dotyczy`. It assigns an absence solely from semantic `workTimeType.isAbsence`, so L4, UW, art.188, and custom absence types use the one absence row. The absence-period report remains independently grouped by absence code and was not given a shift field.

Each report input reaches exactly one pivot row. `suma`, `sumaBezNadgodzin`, and each dynamic work-time-type counter are accumulated only in that row. Overtime detection and exclusion from `sumaBezNadgodzin` occur once per input record. Consequently, for the requested example the rows are: I = 40, II = 30, III = 20, Brak danych = 4, and Nie dotyczy = 8. Their sum is 102 h exactly once; worked time is 94 h and absence is 8 h. No absence or overtime is copied to another shift row. The executed analytics test independently exercises the same structure with I/II/III, historical null, absence, dynamic types, parsed XLSX, and an explicit 58 h source-to-row conservation check.

The API/UI, CSV generation in `ReportsView.tsx`, and XLSX export all use one readable `Zmiana` column after `Pracownik`; there are no `I zmiana`, `II zmiana`, or `III zmiana` aggregate columns. XLSX values are emitted as numbers, uses the same rows as the API, and the generic exporter retains frozen headers and full-width autofiltering.
