## 7. Closure Control regression analysis

**PASS for valid model data and tested scenarios; no arithmetic regression detected.**

The base computes employee hours by adding worked-row `suma` and non-NN dynamic hours from ABSENCE rows. The new report has a single combined row, so that old branch could no longer identify absence rows. The implementation instead computes:

```text
totalEmployeeHours = round2(sum(row.suma + sum(non-NN absence columns)))
                  = round2(N + O + P)
totalSettledHours  = round2(order hours + P)
difference        = round2(totalSettledHours - totalEmployeeHours)
```

Crucially, `row.sumaBezNadgodzin` is destructured out and never added to Closure Control totals. It already contains P, but that does not double count P because it is not an input to the control sum. Work-type dynamic columns are excluded using `absenceCodes`. NN is explicitly excluded even if present in that set. Overtime is already in `suma`, so it is counted exactly once.

The `absenceTypes` query existed at the base commit; it is not a newly introduced query. It selects metadata-classified absences plus NN, without an active-only filter. Under the schema's required work-time-type relation and the same RepeatableRead snapshot, its classification matches the metadata included with employee entries. Custom absences are included automatically.

The transaction wrapper, RepeatableRead isolation, maxWait/timeout, diagnostics contributions, difference/status checks, and server invariant guard remain unchanged. All helper reads continue to use `tx`. The independent comparison asserted complete equality of base/current Closure Control responses in all 16 scenarios, and verified two separate RepeatableRead callbacks per comparison.

An absence linked to an included order retains the existing positive discrepancy: it occurs once on the employee side but twice on the settled side (order hours plus absence hours). Diagnostics must still flag that historical inconsistent record. The +8 probe and retained Direction B tests confirm this behavior; it is not a new double-counting regression. Unassigned work still yields a negative contribution, and NN yields neither.

The approved plan §12 literally says Closure Control logic is out of scope. This shape-dependent adaptation is necessary to preserve its behavior, and is justified mathematically; the handoff should explicitly distinguish the compatibility adaptation from a business-rule change. The extra debug logging and date fallback are not required by that adaptation (R1/R4).
