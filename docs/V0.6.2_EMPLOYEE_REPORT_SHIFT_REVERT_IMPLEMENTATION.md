## 5. New Calculation Logic Implemented

### `getEmployeeReportRows()` - New `sumaBezNadgodzin` Accumulation:

```typescript
if (!isAbsence) {
  // Work entry: counts toward both totals
  pivot[employeeId].suma += hours;
  if (!isOvertime) pivot[employeeId].sumaBezNadgodzin += hours;  // Normative work
} else if (code !== UNPAID_ABSENCE_CODE) {
  // PAID absence (UW, L4, UOK, UŻ, WKU, etc.): only in sumaBezNadgodzin
  pivot[employeeId].sumaBezNadgodzin += hours;
  // NOT added to suma (client: suma = worked hours only)
} else {
  // NN (unpaid): excluded from BOTH totals, only in dynamic column
}
```

### Closure Control Summary - Updated `totalEmployeeHours` Calculation:

```typescript
// Build a set of absence codes for filtering (from absenceTypes already fetched above)
const absenceCodes = new Set(absenceTypes.map((t) => t.code));
const totalEmployeeHours =
  Math.round(
    employeeRows.reduce((sum, row) => {
      // Each row is one employee (no shift breakdown).
      // suma = worked hours with overtime.
      // Dynamic columns contain both work and absence hours.
      // We need: worked hours (suma) + paid absence hours from dynamic columns (excluding NN).
      const { employeeId, employeeName, suma, sumaBezNadgodzin, ...counts } = row;
      const absenceHours = Object.entries(counts).reduce((hours, [code, value]) => {
        if (code === UNPAID_ABSENCE_CODE) return hours;
        if (!absenceCodes.has(code)) return hours;
        return hours + (Number(value) || 0);
      }, 0);
      return sum + Number(suma) + absenceHours;
    }, 0) * 100,
  ) / 100;
```

The `absenceTypes` query used to build this filter already existed in base
`84c576a`; it was not introduced by v0.6.2 and is not a new query. `sumaBezNadgodzin`
is destructured out and never added to the control total, so paid absence hours
are counted exactly once.

## 11. Closure Control Failure Investigation

### Historical working-tree failures
While implementing the change, the test suite was red in the working tree. The
earlier draft of this report claimed **22 failures** and then broke them down
into groups that summed to **23**. That number and breakdown were not derived
from a preserved log, are not reproducible from the final repository state, and
must not be treated as an established fact. The review correctly flagged this.

What the final code and tests do establish:

- The change to `getEmployeeReportRows()` replaced a per-`employee × shift`
  output shape with a single row per employee, so `getClosureControlSummary()`
  could no longer distinguish absence rows by `row.workShift === 'ABSENCE'`.
- Test mocks that returned all work-time types for every `workTimeType.findMany`
  call did not model the real query, which requests absence types plus `NN`.
  This is a genuine mock defect independent of the shape change.
- The `absenceTypes` query itself already existed in base `84c576a`; it is not a
  new query. Only the way its result feeds `totalEmployeeHours` changed.

The final green suite therefore reflects both (a) expected-value updates required
by the new single-row shape and (b) repair of inaccurate mocks. The report does
not assert that every historical failure was exclusively a mock issue.

### Base v0.6.1 Comparison
Independently verified: all tests pass on base commit `84c576a` (v0.6.1), and
the reviewed implementation. The v0.6.2 shape change is the source of the
expectation/mocks updates.

### Application Regressions Found
**NONE** in the final code. The core application arithmetic is correct and
matches the client requirements; this was confirmed by the independent review's
16 base/current scenarios.

### Closure Control Code Changes
**Changed from v0.6.1:** YES

**Rationale:** The `totalEmployeeHours` calculation in `getClosureControlSummary()` had to be updated because:
1. Old: Multiple rows per employee (shift + absence), checked `row.workShift !== 'ABSENCE'`
2. New: Single row per employee, all hours in dynamic columns, `suma` = worked hours only

**New Implementation:**
```typescript
const absenceCodes = new Set(absenceTypes.map((t) => t.code));
const totalEmployeeHours = Math.round(
  employeeRows.reduce((sum, row) => {
    const { employeeId, employeeName, suma, sumaBezNadgodzin, ...counts } = row;
    const absenceHours = Object.entries(counts).reduce((hours, [code, value]) =>
      hours + (code === UNPAID_ABSENCE_CODE ? 0 : (absenceCodes.has(code) ? Number(value) || 0 : 0)), 0);
    return sum + Number(suma) + absenceHours;
  }, 0) * 100,
) / 100;
```

This correctly computes: `worked hours (suma) + paid absence hours (from dynamic columns, filtered by absenceCodes, excluding NN)`.

### Test Infrastructure Changes
The closure/reconciliation failures were addressed by updating the
`workTimeType.findMany` mocks to properly handle the `absenceTypes` query (which
filters by `OR: [{ isAbsence: true }, { code: 'NN' }]`):
- Return only absence types when `isAbsenceQuery` is true
- Return all work time types for other queries (e.g., `getEmployeeReportTypes`)

plus the expected-value updates required by the new single-row shape. No
production business logic was changed to make tests pass.
