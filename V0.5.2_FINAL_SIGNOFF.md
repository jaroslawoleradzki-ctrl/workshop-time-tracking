## 2. Five concurrency cases

The scenarios are deterministic mocks, not PostgreSQL multi-session integration tests. Each scenario defines a transaction-client State A and a newer/global State B. The endpoint invokes production reconciliation code, while the mocked interactive transaction supplies the same `txMock` to all reconciliation reads. The asserted results show that State B does not leak into the returned State A calculation.

### INSERT: FAIL

- Executable test exists at `backend/tests/analytics.test.ts` under `CASE 1 — INSERT`.
- It models State A with 40 hours and State B with a newly inserted unassigned 8-hour report.
- It verifies transaction-client reads and proves that the global 48-hour state does not leak into the 40-hour response.
- The successful response is `MATCHED` with no diagnostics. It therefore does not meet the explicit requirement for this case to return a successful `MISMATCHED` response and verify the rounded diagnostics/difference invariant.

### UPDATE: PASS

- Executable test exists under `CASE 2 — UPDATE`.
- It models an 8-hour State A report and a newer 16-hour State B report.
- The response continues to use State A across totals and diagnostics.
- It returns `MISMATCHED` with `difference = -8` and diagnostic contribution sum `-8`; for these exact integer values the required two-decimal rounded equality holds.

### SOFT DELETE: PASS

- Executable test exists under `CASE 3 — SOFT DELETE`.
- It models an active unassigned 8-hour report in State A and its omission after soft deletion in State B.
- The response consistently retains the State A report in totals and diagnostics.
- It returns `MISMATCHED` with `difference = -8` and diagnostic contribution sum `-8`; the required two-decimal rounded equality holds.

### ORDER ENTERS CLOSURE: PASS

- Executable test exists under `CASE 4 — ORDER ENTERS CLOSURE`.
- State A has a CLOSED order with `completionDate` outside the requested period; State B exposes that order as OPEN, which enters closure because it has report hours in the period.
- State A closure membership is used consistently by order totals and diagnostics; the newer global membership does not leak.
- It returns `MISMATCHED` with `difference = -40` and diagnostic contribution sum `-40`; the required two-decimal rounded equality holds.

### ORDER LEAVES CLOSURE: FAIL

- Executable test exists under `CASE 5 — ORDER LEAVES CLOSURE`.
- It models an OPEN order included in closure in State A and a newer SUSPENDED State B where it leaves closure.
- The response consistently uses State A and does not leak the newer global order state.
- The successful response is `MATCHED` with no diagnostics. It therefore does not meet the explicit requirement for this case to return a successful `MISMATCHED` response and verify the rounded diagnostics/difference invariant.

The negative invariant-guard test is separate and was not used as a substitute for any of these case decisions.
